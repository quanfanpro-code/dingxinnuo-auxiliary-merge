# 鼎信诺辅助核算合并与核对

用于处理鼎信诺导出的账表，将辅助核算信息归入序时账或科目余额表，并核对处理前后的完整性、归属和金额。

这是供支持 Skill 的 AI 助手读取的处理规范，包含字段说明和验收场景。实际文件读取、匹配、生成与核对由助手及其可用表格工具执行；本仓库未包含独立运行的数据处理程序。

## 支持的两种处理

| 输入 | 输出 |
|---|---|
| 序时账＋核算项目明细表 | 补充辅助核算、一级编码及一级科目，精简无须展示的列，原分录行数和金额不变 |
| 科目余额表＋核算项目余额表 | 主表保留 8 个必要列，在原科目下展开辅助项目，必要时增加“未列明辅助项目”行 |

可以只处理其中一组。

余额表为空或异常时，会先勾稽已提供的四张表。有可靠期初和完整序时账时，可重建对应科目或项目余额；只有本期分录时，恢复本期发生额及辅助归属，未知期初归属列入“未列明辅助项目”。详细规则见 [四表勾稽与余额重建](references/四表勾稽与余额重建.md)。

序时账默认不展示“对方科目名称”“№”“会计年”“会计月”。在“科目编号”前新增“一级编码”和“一级科目”：一级编码取原科目编号前四位并保持文本，一级科目按同账套科目资料匹配；内部匹配与期间核对仍使用完整源数据。

余额表主表默认保留：**科目编号、科目名称、辅助核算信息、借贷方向、期初余额、借方发生额、贷方发生额、期末余额**。重复金额列只展示一份，独立的以前年度、调整等信息放入核对明细。列精简不缩小核对范围，全部原金额列仍需验证并保留映射。

余额、发生额、外币金额等输出为真正的 Excel 数值，数量、单价和汇率也按原精度保存为数值，可直接参与计算。科目编号、凭证编号等标识保留文本及前导零。

## 核心规则

- 同一业务范围有多个辅助维度时，只选一个维度，优先选择能识别对方单位或个人的维度；该维度下的所有合法明细保留。
- 不固定优先职员，也不一律排除部门。只有部门信息的记录正常保留。
- 无法确定哪个维度代表实际交易对方，或无法确定维度覆盖范围时，列出客户确认事项，不自行猜测。
- 正常合并以科目余额表为控制数；来源异常时，先用可靠期初和序时账验证或重建控制数，保留原值、重建值及差额。不能把空辅助余额表直接当成没有辅助业务。
- 先查现有四表能否相互证明，无法查明的维度含义或关键期初依据再请客户确认。本期恢复与完整余额重建分别报告，不推定本期出现的对象承接全部期初。
- 保留来源定位、维度选择依据、补差前后差额及异常状态。
- 原文件只读，不把科目行与辅助行或上下级科目混合加总。

## 验证要求

处理前识别文件真实格式、账套与期间、币种、关键字段、科目层级和金额精度，建立行数及金额基准。

处理后：

1. 序时账保留字段逐行一致，辅助对象及一级科目归属正确，一级编码为文本，借贷合计及分科目、分期间汇总一致；文本金额转换后数值不变。
2. 正常合并原科目和所选辅助金额不变；重建部分逐项核对期初、分录及计算关系并列明原表差异。全部金额列按各自期间及依据核对，未知历史或调整数据不填零冒充通过。
3. 原辅助记录都有明确去向；匹配失败、歧义及金额不符单独列明。
4. 保存后重新读取最终文件，逐个检查非空金额为数值类型，并按列映射核对被精简的字段。补差后为零不能代替来源和归属检查。

## 安装

将本仓库完整放入所用助手的技能目录，文件夹命名为 `dingxinnuo-auxiliary-merge`，保留相对目录结构。

Windows 上，Codex 的常见用户技能目录为 `%USERPROFILE%\.codex\skills`。例如在 PowerShell 中：

```powershell
git clone https://github.com/quanfanpro-code/dingxinnuo-auxiliary-merge.git "$env:USERPROFILE\.codex\skills\dingxinnuo-auxiliary-merge"
```

如果使用统一技能目录及目录联结，放入已有统一目录并沿用现有入口；不要建立多个维护副本。目标文件夹已有内容时先检查，不直接覆盖。

## 使用

在支持技能调用的助手中输入：

```text
请使用 $dingxinnuo-auxiliary-merge 处理我提供的鼎信诺导出文件。
为序时账补充辅助核算，并将两个余额表合成带辅助项目的余额表。
只保留能识别对方单位或个人的辅助维度；无法判断时列出客户确认问题。
完成处理前后验证，交付合并表、核对结果和未解决事项。
```

提供文件或目录，并说明需要处理哪一组。有些 `.xls` 实际为带引号的制表符文本，应按真实格式读取。不同导出版本的字段及期间口径需要重新核实。
