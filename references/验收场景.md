# 验收场景

这些场景用于检查处理规则或后续脚本的行为，不能仅检查文件中是否出现某个词。使用新建测试文件；不改写客户原件。金额使用定点数，校验保存后重新读取的结果。

| 场景 | 预期行为 |
|---|---|
| 同一分录按部门、具名职员各列 100 元，确认均覆盖该分录 | 序时账仍一行，保留职员，原金额 100 元，不加计成 200 元；排除记录可追溯 |
| 某科目只有部门 A 60 元、部门 B 40 元 | 两条部门项目均保留，不套用其他科目的去重决定 |
| 同一科目客户和部门都覆盖 100 元，客户为具名单位 | 保留客户维度全部明细，部门作为重复维度排除 |
| 同科目客户、供应商均为具名单位，缺少角色依据 | 列具体客户确认问题，不按固定类型优先级猜选 |
| 部门合计 100 元、职员合计 80 元，覆盖关系不明 | 先查口径和覆盖范围，必要时问客户；不能直接选择职员并补 20 元后报告通过 |
| 同名项目有两条相同金额，但属于不同凭证或币种 | 分别保留在各自范围内，不能按名称金额去重 |
| 同一分录身份字段匹配但借方金额一表 100、一表 110 | 报告金额不符，不把其当成没有辅助信息，也不强行匹配 |
| 主表分录键重复或同科目编号因币种出现两行 | 补充分组键或待确认；不能字典覆盖或连接扩行 |
| 辅助来源行没有主表对应科目或分录 | 列未匹配异常及来源位置，不能静默丢弃 |
| 同一分录同维度两个项目分摊 60 元和 40 元，有明确分摊依据 | 辅助列完整写出两项目及金额，原分录仍一行；分摊合计等于原分录 100 元 |
| 某科目无任何辅助来源记录 | 保留原科目行，不再复制一条同额未列明行 |
| 当前金额全部一致，只有以前年度列差 30 元 | 新增未列明行，对应以前年度列为 30 元，其他列按实际差额填写 |
| 补差后金额为零，但原辅助项目错归另一个科目 | 归属检查失败，不能以补差后为零认定通过 |
| 上级科目 100 元，下级 60 元和 40 元，辅助 100 元 | 同层级控制总额为 100 元，不能把整表加成 300 元 |
| 金额空白意义不明、非法数值或缺少金额列 | 报告缺失或解析异常，不能默认零并补差 |
| 输出借贷总额相同，但两个对象的辅助名称互换 | 逐行来源映射检查失败，总额相同不足以通过 |
| CSV 金额为文本 `"1,234.50"`，编号为 `"0012"` | 金额保存为数值 1234.50 并设置两位小数格式；编号仍为文本 0012；保存后逐单元格验证 |
| 单元格外观为两位小数，但底层仍是文本 | 类型验收失败，必须转换真实值，不能只设置数字格式 |
| 单价 0.123456、汇率 7.1234、数量 1.2345 | 保存为数值并保留各自精度，不统一截成两位小数 |
| 账面、未审、审定期末逐行一致 | 主表只展示一次，列映射可还原三列；原始全部金额列继续核对 |
| 借方、贷方两列逐行碰巧相同，或只有合计相同 | 保留两个独立指标，不能据此合并列 |
| 审定期末与账面期末有差异，或以前年度含独立数据 | 主表按既定账面口径，差异及历史数据保留在核对明细，不丢弃 |
| 附加调整列全为数值零，另一列全为空 | 可不展开两列，但映射分别记为全零、全空；回读还原时区别对待 |

## 补差的算术基准

按“期初、借方发生、贷方发生、期末”排列：

1. 借方自然方向：主表 `[100, 50, 20, 130]`，所选项目合计 `[80, 40, 10, 110]`。
   - 未列明行应为 `[20, 10, 10, 20]`。
   - 检查逐列相加还原主表，以及 `20＋10－10＝20`。
2. 贷方自然方向：主表 `[-10, 40, 15, -35]`，所选项目合计 `[0, 0, 5, 5]`。
   - 未列明行应为 `[-10, 40, 10, -40]`。
   - 检查逐列相加还原主表，以及 `-10－40＋10＝-40`。负差额不取绝对值。
3. 原表有 3 条科目行，其中第一个科目有 2 条所选项目且需 1 条未列明行，其他科目没有辅助来源。
   - 输出应为 `3＋2＋1＝6` 条数据行；不是把所有科目都补成有辅助行。

## 验证结论

结构校验只证明 skill 的格式可用；算术校验只证明计算示例正确。真实交付仍须按主文件要求验证最终工作簿的原字段、来源归属、维度决定、每列金额和异常状态。没有实际运行的场景不能宣称已经通过实测。
