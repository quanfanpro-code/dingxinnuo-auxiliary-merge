# 鼎信诺导出字段与读取说明

## 文件读取

这些是已见导出特征，读取新客户文件时需要重新验证，不能硬编码为所有版本通用。

- `.xls` 文件可能是 GBK 编码的制表符文本，字段被双引号包裹。
- 先查文件头和样本，区分真实 XLS、XLSX、文本或 HTML；根据真实格式选择已安装读取工具。
- 文本使用支持引号、制表符和字段内换行的 CSV 解析器。Python 示例参数为 `encoding="gbk", newline=""` 和 `delimiter="\t"`；编码应先验证，禁止用忽略错误方式读取。
- 已见文本末尾有一个空标题列。只有确认整列为空时才可省略；空标题下有值应列为异常。重复标题必须区分，不能让字典读取静默覆盖。
- 不全局删空格或修改原值；用于匹配的规范化键与原始展示值分别保存。
- CSV 导入为字符串时，写入 Excel 前显式转换金额、数量、单价、汇率等计算列。金额的逗号分隔符属于显示格式，不能把含逗号的文本原样作为数值存储。
- 表头行、空行、汇总行分别识别并记录；记录数指实际数据行数。

## 序时账字段

已见唯一键：

`会计月、记账时间、凭证编号、凭证种类、编号、科目编号、借方发生额、贷方发生额`

辅助描述列：

`核算项目类型名称、核算项目名称`

以实际导出为准加入账套、年度或币种，防止跨范围碰撞。不要把“编号”未经验证地当成分录号。只按凭证号匹配不能区分一张凭证内的多条分录。

完整键未匹配但身份字段唯一相同时，应展示两表金额差异；不得用去掉金额字段的连接悄悄接受。

“对方科目名称、№、会计年、会计月”默认不在输出中展示，但读取和匹配阶段保留完整数据。新增“一级编码”取科目编号前四位并存为文本，“一级科目”依据同账套科目字典或科目余额表中的一级科目行匹配。先确认科目层级支持四位一级编码；不能将任意四位前缀或上级名称直接当作可靠一级科目。

## 余额表字段映射

已见两表共同字段包括科目编号、科目名称、借贷方向及大量金额列。

已见科目表非金额字段：

`№、上级科目名称、科目编号、科目名称、科目类别、借贷方向、是否明细科目、科目级次、科目附加信息`

不能简单把新文件中其他所有列都认作金额；必须检查列含义和数据类型。下列名称差异曾在一组导出中得到核实，新文件仍需检查：

| 科目余额表 | 核算项目余额表 |
|---|---|
| 未审上期借方发生额 | 未审上年借方发生额 |
| 未审上期贷方发生额 | 未审上年借贷发生额 |
| 未审上期发生额 | 未审上年发生额 |
| 审定上期借方发生额 | 审定上年借方发生额 |

“未审上年借贷发生额”疑似导出标签问题，在已见样本中对应上期贷方发生额。不能仅因名称相似就套用映射；需要同期间同口径的相关列、导出说明或客户确认支持。无法确认时保留待确认项，不用零填缺列。

一组样本有 49 个金额列，此数量不是固定要求。列出新文件全部金额列，给出逐列映射，映射不齐就不能报告全部金额列已核对。

主表默认 8 列，其中金额列对应 `账面期初数、账面借方发生额、账面贷方发生额、账面期末数`，分别显示为 `期初余额、借方发生额、贷方发生额、期末余额`。其他列按主文件的精简规则归入核对明细或映射说明。展示映射和两张源表之间的字段映射分别记录，不能混为一谈。

## 金额和方向

- 千位分隔符、负号、括号负数等按已确认格式解析；非法金额保留位置并报错。
- 余额可能按科目自然方向存为有符号数。确认后，借方自然方向通常为“期末＝期初＋借方发生－贷方发生”，贷方自然方向通常为“期末＝期初－借方发生＋贷方发生”。
- 对调整、审定、以前年度等字段，先确认它们的关系和期间，再检查，不把本期公式套到累计或净额字段。
- 跨科目汇总先统一符号。反向余额和负数本身不代表数据错。
- 期间不能仅从文件名或序时账最大日期推断。余额表可能截止上月，序时账包含本月数据。

## 可追溯记录

处理时保存来源记录号与输出行号的对应，区分来源明细和计算行；文本逻辑记录号不一定等于物理行号。

科目主行和辅助行同时展示时，应在核对结果中说明汇总口径：按科目汇总用末级科目行；按辅助项目分析用对应辅助行，不能整表直接求和。
